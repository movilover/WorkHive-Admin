Third Generation — Referral Network

Device/IP ডেটা এখনো সংগ্রহ হচ্ছে না।
এই মুহূর্তে ডুপ্লিকেট শনাক্তকরণ শুধু ফোন নম্বরের উপর ভিত্তি করে কাজ করছে (যেসব ইউজারের একই ফোন নম্বর সেভ করা আছে)। ডিভাইস ও IP ভিত্তিক শনাক্তকরণ চালু করতে হলে — অর্থাৎ কেউ ভিন্ন ফোন নম্বর দিয়েও একই ফোন/ব্রাউজার থেকে একাধিক অ্যাকাউন্ট খুললে তা ধরতে — আপনার লাইভ সাইটের (User App) রেজিস্ট্রেশন কোডে নিচের অংশটুকু যোগ করতে হবে, যাতে প্রতিটি ইউজারের Firestore ডকুমেন্টে deviceId ও ipAddress ফিল্ড সেভ হয়:
রেজিস্ট্রেশন সফল হওয়ার পরে (Firestore-এ user doc তৈরি করার সময়)
// 1) ডিভাইস ফিঙ্গারপ্রিন্ট লোড করুন
import FingerprintJS from 'https://cdn.jsdelivr.net/npm/@fingerprintjs/fingerprintjs@4/dist/fp.esm.min.js';
const fp = await FingerprintJS.load();
const { visitorId } = await fp.get();   // এই ডিভাইসের জন্য স্থায়ী একটি আইডি

// 2) পাবলিক IP সংগ্রহ করুন (ঐচ্ছিক, ব্যর্থ হলে খালি থাকবে)
let ipAddress = '';
try {
  const r = await fetch('https://api.ipify.org?format=json');
  ipAddress = (await r.json()).ip;
} catch (e) {}

// 3) ইউজার ডকুমেন্টের সাথে সেভ করুন
await setDoc(doc(db, 'users', newUser.uid), {
  ...otherUserFields,
  deviceId: visitorId,
  ipAddress,
}, { merge: true });
এটা যোগ করার পর নতুন সাইন-আপ করা ইউজারদের ক্ষেত্রে ডিভাইস/IP ম্যাচিং স্বয়ংক্রিয়ভাবে এই প্যানেলে কাজ শুরু করবে। প্রয়োজনে লগইনের সময়ও একই কল চালিয়ে বিদ্যমান ইউজারদের ডকুমেন্ট আপডেট করা যায়।

Job Approvals

ইউজারদের পোস্ট করা জব শুধুমাত্র আপনার অনুমোদনের পরেই Worker দের কাছে দৃশ্যমান হবে। Admin নিজে জব পোস্ট করলে তা সাথে সাথেই Live হয়ে যাবে এবং প্রয়োজনে পরে Edit বা Delete করা যাবে। জব Reject বা Delete করলে ইউজারের হোল্ড করা বাজেট (যদি থাকে) স্বয়ংক্রিয়ভাবে তার ওয়ালেটে ফেরত যাবে।

Task Submissions

Task approve করলেই Worker এর balance credit হবে। Reject করলে কোনো balance change হবে না — 💬 আইকনে ক্লিক করে reason লিখলে সেটা Worker-এর নোটিফিকেশনে ও টাস্ক হিস্টোরিতে দেখাবে। User-পোস্ট করা জবের সাবমিশন এখন সেই জব-পোস্টার নিজেও তার User App থেকে Approve/Reject করতে পারে — সেক্ষেত্রে এখানে স্ট্যাটাস ইতিমধ্যে আপডেট দেখাবে। Submission মুছে ফেললে (Delete) সংশ্লিষ্ট স্ক্রিনশটও Firebase Storage থেকে স্থায়ীভাবে মুছে যাবে।
WorkerTask / JobProofRewardDateStatusActions

Deposit Requests

শুধুমাত্র আপনার Confirm এর পরেই User এর Balance আপডেট হবে। 💬 আইকনে reason লিখে Reject করলে User নোটিফিকেশনে কারণ দেখতে পাবে।
UserMethodAmountTxID / SenderDateStatusActions

Withdrawal Requests

Withdrawal শুধুমাত্র আপনার Send/Complete করার পরেই সম্পন্ন হবে। Reject করলে Amount ফেরত যাবে এবং 💬 কারণ User-কে জানানো হবে।
UserMethodRequestedNet AmountAccount / WalletDateStatusActions

OneSignal Push Notifications
এটা সেট করলে অ্যাডমিন প্যানেল থেকে যেকোনো action (Task Reject, Withdrawal Processing/Sent, Deposit Confirm/Reject, Job Approve/Reject ইত্যাদি) এর সাথে সাথেই ইউজারের ফোনে আসল push notification (heads-up পপআপ + সাউন্ড) পাঠানো হবে — শুধু in-app notification list-এ না।
২০২৪ সালের নভেম্বরের পর OneSignal পুরনো ("Legacy") REST API Key বাতিল করে নতুন "Rich" API Key চালু করেছে, এবং পুরনো Legacy App API Key ২০২৬-এর Q1 থেকে সম্পূর্ণভাবে অচল হয়ে যাচ্ছে। নিচের REST API Key ফিল্ডে অবশ্যই OneSignal Dashboard → Settings → Keys & IDs থেকে নতুন Rich API Key ব্যবহার করুন — পুরনো (legacy) key দিলে push পাঠানো ব্যর্থ হতে পারে।
এই App ID টা পাবলিক (secret না) এবং তোমার Android অ্যাপে (MainActivity.java, OneSignal.initWithContext) যেটা বসানো আছে সেটাই এখানে আগে থেকে বসানো আছে। ভিন্ন App ID ব্যবহার করলে দুটো জায়গায় মিলছে কিনা নিশ্চিত করো।
⚠️ এই key টি secret — এটা browser-এ localStorage-এ save হয়। শুধু বিশ্বস্ত ডিভাইস থেকে এই admin panel access করুন।

জরুরি — একটা ধাপ এখনো বাকি
এই admin panel পুশ পাঠানোর সময় নির্দিষ্ট ইউজারকে target করে Firebase UID দিয়ে (OneSignal "External ID")। কিন্তু কোনো ইউজারের ফোন OneSignal-কে তার Firebase UID জানায় না, যতক্ষণ না আপনার লাইভ সাইটের (movilover.github.io/WorkHive) কোডে লগইনের পরে এই কল যুক্ত করা হয়:
Firebase Auth login-এর ঠিক পরে ও logout-এর সময়
// লগইন সফল হওয়ার পরে — এই ডিভাইসকে ইউজারের সাথে লিংক করুন
if (window.Capacitor?.Plugins?.OneSignal) {
  window.Capacitor.Plugins.OneSignal.login({ externalId: firebaseUser.uid });
}

// লগআউটের সময় — পরের ইউজার আগের ইউজারের পুশ যাতে না পায়
if (window.Capacitor?.Plugins?.OneSignal) {
  window.Capacitor.Plugins.OneSignal.logout();
}
এই লাইনটা যোগ না করলে, এই admin panel থেকে push পাঠানো হলেও OneSignal জানবে না কোন ফোনে পাঠাতে হবে — তাই কিছুই পৌঁছাবে না। ✅ WorkHive User App-এর সর্বশেষ ফিক্সড কোডে এই লাইনগুলো ইতিমধ্যে যোগ করা আছে (login/logout handler-এ onesignalLogin/onesignalLogout কল)।
